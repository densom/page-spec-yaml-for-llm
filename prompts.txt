================================================================================
                    PAGE-SPEC YAML: EXAMPLE PROMPTS FOR CLAUDE CODE
================================================================================

These prompts demonstrate how to use Page-Spec YAML files with Claude Code
for AI-assisted UI development. Copy and paste these into Claude Code to see
the power of structured specifications.

Before starting: Run `npx serve page-specs` and open http://localhost:3000
to browse the specs visually.

================================================================================
                         1. UNDERSTANDING SPECS
================================================================================

These prompts help you explore and understand the specifications.

--------------------------------------------------------------------------------
PROMPT 1.1: Analyze a Page Spec
--------------------------------------------------------------------------------

Read page-specs/pages/product-detail.ui.yaml and explain:
1. What components are used on this page?
2. What user interactions are possible?
3. What data bindings (dynamic values like {product.name}) are present?
4. How does this page connect to other pages?

--------------------------------------------------------------------------------
PROMPT 1.2: Understand a User Flow
--------------------------------------------------------------------------------

Read page-specs/flows/02.00-browse-and-purchase.flow.yaml and:
1. List all the pages involved in this flow
2. Identify the decision points and their branches
3. Explain the alternate flows (like guest checkout)
4. Describe the error handling scenarios

--------------------------------------------------------------------------------
PROMPT 1.3: Compare Layouts
--------------------------------------------------------------------------------

Read all layout files in page-specs/layouts/ and compare them:
1. What's different between marketing and dashboard layouts?
2. Which layout would be best for a user settings page?
3. How do the navigation items differ between public and authenticated layouts?

--------------------------------------------------------------------------------
PROMPT 1.4: Generate a Site Map
--------------------------------------------------------------------------------

Read all files in page-specs/pages/ and generate:
1. A complete sitemap showing all routes
2. Group pages by their auth requirements (public, authenticated, admin)
3. Show which layout each page uses

================================================================================
                         TIPS FOR EFFECTIVE PROMPTS
================================================================================

1. REFERENCE SPECIFIC FILES
   Always point to exact file paths so Claude knows what to read.

   Good: "Read page-specs/pages/cart.ui.yaml"
   Bad:  "Read the cart page spec"

2. SPECIFY OUTPUT FORMAT
   Tell Claude what technology stack you want.

   Good: "Generate a React component with TypeScript and Tailwind CSS"
   Bad:  "Generate a component"

3. FOLLOW EXISTING PATTERNS
   Reference existing files as examples.

   Good: "Follow the patterns in page-specs/pages/account.ui.yaml"
   Bad:  "Create a page spec"

4. BE SPECIFIC ABOUT SCOPE
   Clarify what you need generated.

   Good: "Just the React component, not the API"
   Bad:  "Generate the feature"

5. ASK FOR VALIDATION
   Request verification against schemas.

   Good: "Verify the output matches the ui-spec.schema.json schema"

5. Try Prompt 3.1 to create your own spec

6. Iterate: spec → generate → refine → repeat
